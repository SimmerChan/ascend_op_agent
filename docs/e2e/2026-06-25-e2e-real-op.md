## 发现的真 bug

### Bug 1:codegen prompt 没让 LLM 用 file_write 工具

`src/ascend_op_agent/orchestrator/graphs/new_dev.py:153-162`(修复前)：

> "输出:**kernel.cpp + op.cpp 文件内容**。"

LLM 老实把代码塞进 assistant 文本回复。`code_result.files` 始终为空,compile resolver 拿不到路径,直接 raise。

**修复**(同文件):prompt 改为显式列 5 个文件 + 每个 `file_write(path, content)` + 写完回 `codegen done` 一行。

### Bug 2:phase_callback 收到 str 而不是 dict

`src/ascend_op_agent/orchestrator/state_machine.py:178-185` `_emit_phase(phase, event, error: Optional[str])` 失败时把 `str(e)` 直接当 payload 传给 callback。回调期望 dict(`payload.keys()`),log 报:

> `phase_callback error: 'str' object has no attribute 'keys'`

**修复**:`_emit_phase` 内部统一打包 `payload = {} if error is None else {"error": error}`,callback 永远收到 dict。

## 暴露的更深架构 gap(未修,待 follow-up)

### Gap 1:agent 不向编排器暴露 tool_call args

`src/ascend_op_agent/agent/core.py:90`:

```python
self._conversation_history: list[dict[str, str]] = []
```

LLM 调 `file_write(path="/tmp/.../op_kernel.cpp", content="...")` 时,`agent/core.py:221-228` 只往历史里塞 `"content": f"tool_call({name})"`,**不存 args**。编排器拿不到 file_write 实际写的路径,`code_result.files` 只能空。

**修复方向(三选一)**:
1. **side-channel**:`file_write` tool 内部把 (path, content) 写到 `agent._tool_results` 列表,`make_llm_node` 后读取
2. **disk 扫描**:codegen_node 后扫约定的 `LOCAL_WORKDIR`,读到的文件塞 `code_result.files`
3. **扩展 _conversation_history**:把 tool_call 改成 `{"role": "tool_call", "name": ..., "args": ..., "result": ...}`,破坏同形契约,需 plan 评审

最小路径是 #2,在 e2e 脚本里加一个 `local_codegen_node` 工厂,跑 LLM 后扫盘。

### Gap 2:cannbot skill description 路由质量未验证

plan 里 U3 要"3 个阶段 prompt × 3 个 skill description ≥2/3 路由正确",**实际从未跑过**真实 LLM 路由。e2e 里 `use_real_skill_bundles=True` 是按 phase 显式注入,不是 LLM 路由。

### Gap 3:backend.py `_orchestrator` 仍为 None

`backend.py:45`:`_orchestrator = None`。U7 提交了 CheckpointStore init + resume RPC,但 Orchestrator 实例从未接入。生产路径 `ascend-op-agent run` 仍走原 AIAgent ReAct,**不进 PhaseRunner**。

e2e 脚本绕开 backend.py 直接调 `build_new_dev_graph`,所以跑通了。但 CLI 用户实际拿不到这条路径。

## 结论

- **架构骨架 OK**:PhaseRunner / CheckpointStore / make_llm_node / NpuExecutor / SSH 容器拓扑 / HITL interrupt-resume 在真实 LLM + 真实 NPU 上工作
- **架构 gap 真实存在**:3 个(见上),需要 follow-up 计划
- **P0 验收不能算"完成"**:跑通 ≠ 用户可用。`ascend-op-agent run` CLI 仍走老 AIAgent
