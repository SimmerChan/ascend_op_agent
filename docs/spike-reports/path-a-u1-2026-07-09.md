## TL;DR

**0/5 ops passed (0%) → NO-GO → 停 U4/U8, 回用户。**

**根因**:**LLM 不会以可解析格式输出 AscendC 代码**。4/5 ops 在 compile 阶段抛 `ValueError: code_result.files 为空, 且 assistant 文本里也抽不到代码块`(LLM 既没用 file_write tool,也没输出 markdown 代码块);1/5 (relu) 走得更远但 LLM 写的 files 没包含 `build.sh`,导致远端 `bash build.sh` 找不到文件。

**Pipeline 本身工作正常**:PhaseRunner → HITL 设计确认 → NPU 远程编译 全链路打通,每次失败点都在 LLM 输出而非基础设施。

## 失败模式分析

### 4/5 ops:`code_result.files 为空`(LLM 输出格式不可解析)

LLM agent 应该:
1. 调 `file_write` tool 写 `op_kernel.cpp` / `op_host.cpp` / `CMakeLists.txt` / `build.sh`
2. 或在 assistant 文本中输出 markdown 代码块(```cpp ... ```)让 `_extract_files_from_messages` 抽取

实际:**LLM 两者都没做**。`code_result.files == []` 且 assistant 文本中没有可识别的 markdown 代码块。e2e_real_op.py line 199-212 的 fallback 抽不到 → 抛 `ValueError`。

LLM agent 在 codegen 阶段产生了什么(text thinking? 不完整 code? 单纯一句话?):**spike 未捕获**,需后续给 prompt 加 verbose log。

### 1/5 ops (relu):`bash: build.sh: No such file or directory`

relu 走到了 compile 阶段(LLM 至少写了部分 files),但 `_extract_files_from_messages` 抽到了一组不含 `build.sh` 的 files,scaffold fallback 没补上(relu 的 LLM 输出可能没给路径注释,导致 extract 失败 → 走了某条 fallback 路径)。

## Spike 期间发现的环境问题

| 问题 | 影响 | 修法 |
|---|---|---|
| `/tmp/e2e_scaffold` 不存在 | spike 启动时 scaffold copy 失败 | spike 脚本本身有 fallback(无 scaffold → 从零编译模式),但实际从 910B pull 更可靠 |
| `/tmp/e2e_scaffold/build/` 是 910B 编译产物(stale .so) | `shutil.copytree` 报 `[Errno 2] No such file or directory` | spike 脚本加 `IGNORE_NAMES = {"build", "__pycache__", ".git"}` 过滤 |
| `from scripts.e2e_real_op import ...` 在 `python scripts/spike.py` 下不工作 | spike 启动报 `ModuleNotFoundError: No module named 'scripts'` | 加 project root 到 sys.path 而非 scripts 目录本身 |
| `~/.ascend_op_agent/.env` + `config.yaml` 不存在 | (实际 LLM 调用成功,推测全局 config 有 fallback 或有别处提供 key) | spike 跑得通,但具体 key 来源待 audit |
